# PoC форми контактів, щоб перевірити дві правки перед refinement

Нотатки з браузера і тестів — у `docs/poc-notes.md`. Код експерименту тимчасовий; у PR лишаються лише документи.

## 1. Гіпотеза

Якщо зробити телефон обов’язковим і зменшити мінімальну довжину повідомлення до 5 символів, форма й API поводитимуться узгоджено, а тести покажуть, де специфікація й код розходяться.

## 2. Налаштування

- Гілка: `day-3`
- Застосунок: `npm.cmd run dev`, in-memory MongoDB
- Перевірка UI: `http://localhost:3000/en/contacts`
- Тести: `npx.cmd jest app/lib/utils/validateContactData.test.ts`, `ContactForm.test.tsx`, `app/lib/utils`

## 3. Зміни (одним реченням кожна)

1. **Телефон на формі** — поле більше не optional; порожнє значення дає помилку на клієнті.
2. **Телефон на API** — порожній або відсутній `phoneNumber` повертає `Phone number is required.`
3. **Мітки й переклади** — зірочка на телефоні, тексти `phoneNumberRequired` (uk/en).
4. **Мінімум повідомлення** — 5 символів у константі сервера, Zod на формі й у текстах помилок uk/en.

## 5. Чекліст «доведено / не доведено / потрібен розробник»

| Зміна | Доведено | Не доведено | Потрібен розробник |
|-------|----------|-------------|-------------------|
| Обов’язковий телефон на UI | Підпис з `*`, помилка при порожньому полі (нотатки) | — | Чи текст uk відповідає AC-01 дослівно? |
| Обов’язковий телефон на API | Тест показує `Phone number is required.` без поля в тілі | Прямий POST у браузері/Postman не перевіряв | Чи той самий текст для `/api/collaboration`? |
| Мінімум повідомлення 5 | 6 символів у браузері проходить | 4 символи в UI не перевіряв | Яке значення погоджує замовник — 5, 10 чи інше (Q з Дня 2)? |
| Узгодженість клієнт/сервер | Змінили 4 очікувані місця для довжини + константа на сервері | — | RULE-05/06 у `contact-form-rules.md` лишилися з 10 — оновлення специфікації? |
| Тести | Червоні тести зафіксовано як знахідки | — | Хто оновлює тести після рішення: команда розробки |

## 6. Рекомендований наступний крок

Узгодити з замовником обов’язковий телефон і фінальний мінімум повідомлення, потім оновити AC/RULE і тести — до merge коду PoC у `main` не використовувати.
